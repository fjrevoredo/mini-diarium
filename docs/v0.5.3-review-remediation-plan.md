## Goal

Implement every actionable remediation from the v0.5.3 branch code review while keeping the code simple, privacy-preserving, and maintainable. The end state is a branch where image storage invariants are enforced consistently, link opening is sanitized at every path, the image picker avoids bulk plaintext payloads, migrations fail cleanly, and validation can run reliably.

## Scope

- Fix the image picker Solid ref so it needs no inline lint suppression.
- Share link URL normalization between link creation and stored-link opening.
- Normalize imported `data:image/...` content into the encrypted image store.
- Replace bulk image-picker loading with summaries plus on-demand image data.
- Validate image MIME, byte size, and magic bytes at the backend storage boundary.
- Align frontend image reference parsing with backend `<img src=...>` semantics.
- Add explicit rollback/error handling to the new v8 to v9 and v9 to v10 migrations.
- Replace fixed-path auth test fixtures with isolated temporary directories if this has not already been fixed by concurrent work.
- Update docs/changelog only where user-visible behavior or durable conventions change.

## Non-Goals

- Do not redesign the image picker UI beyond what is needed for summaries plus on-demand loading.
- Do not add encrypted thumbnails unless the summary-only picker proves unusable without them.
- Do not change the public JSON export format except for preserving current image round-trip behavior through import normalization.
- Do not refactor unrelated editor, auth, import/export, or plugin code.
- Do not run validation commands while the current user instruction to skip tests remains in effect; commands below are the required validation once execution is approved and validation is allowed.

## Assumptions

- Existing low-level `insert_entry()` remains available for unit tests and internal fixture setup.
- User-facing import paths should apply the same image-store invariant as normal editor saves.
- Allowed persisted image formats should match existing app support: PNG, JPEG, GIF, WebP, and BMP.
- Unsupported or invalid image data should produce controlled save/import errors rather than silently storing unsafe or malformed bytes.
- The team may already be fixing auth test failures; that task can be marked `SKIPPED` only after inspecting the branch and confirming equivalent fixture isolation exists.
- Link opening through Tauri opener remains an intentional user action for allowed `http`, `https`, `mailto`, and `tel` URLs.
