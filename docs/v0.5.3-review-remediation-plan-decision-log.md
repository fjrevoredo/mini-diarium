## Purpose

Record implementation decisions that were not explicitly specified in the original remediation plan. Each entry should be added when the decision is made, not after the work is finished.

## Entry Format

- Date: `YYYY-MM-DD`
- Task: plan task number/title
- Decision: compact statement of what changed from the original plan or what choice was made
- Rationale: compact reason the chosen approach was better, safer, or more consistent with the codebase

## Entries

- Date: `2026-06-04`
  Task: plan execution policy
  Decision: Mark tasks `COMPLETED` once implementation and explicitly named test updates are in place, while deferring command-based validation until the later verification window.
  Rationale: The plan already carries forward a standing instruction to defer validation commands during implementation, but the user still asked for live task-state updates during full implementation.

- Date: `2026-06-04`
  Task: Task 4 - Add Backend Image Validation
  Decision: Set the maximum persisted image size to `20 MiB`.
  Rationale: The repo already uses a `20 MB` ceiling for imported custom font binaries, so reusing that scale keeps binary-asset limits consistent and prevents very large plaintext image payloads from being processed or encrypted.

- Date: `2026-06-04`
  Task: Task 5 - Split Image Picker Summary And Data APIs
  Decision: Replace preview thumbnails with metadata cards backed only by image summaries.
  Rationale: The plan explicitly avoids encrypted thumbnail work, and summary-only cards preserve picker usability without decrypting every stored image up front.

- Date: `2026-06-04`
  Task: Task 3 - Normalize Imported Images Into The Image Store
  Decision: Make `insert_entry_with_images(...)` return the inserted entry ID.
  Rationale: The existing low-level insert function remains untouched, and returning the new ID makes the higher-level helper more useful for import tests and future internal callers.

- Date: `2026-06-04`
  Task: Task 4 - Add Backend Image Validation
  Decision: Update affected image-storage tests to use valid image fixtures and distinct supported formats instead of placeholder byte strings.
  Rationale: Once `upsert_image()` enforced magic-byte validation at the storage boundary, tests that were really about association or resolution semantics needed valid image payloads so they would keep exercising the intended behavior.

- Date: `2026-06-04`
  Task: Task 7 - Add Explicit Migration Rollback Helpers
  Decision: Force the v9→v10 rollback test to fail by pre-creating a conflicting table named `idx_entry_images_image_id`.
  Rationale: The earlier view-based conflict no longer failed reliably with the migration's `IF NOT EXISTS` statements, while an object-name collision on the index path deterministically exercises the rollback branch.
