Regression coverage: 4 new Vitest cases in `EditorPanel.integration.test.tsx` (superseded load, image-lookup failure, unmount-with-pending-debounce, type-before-load) against a rewritten editor fake that models `getHTML`/`isEmpty`/`isDestroyed` transitions, 3 new Rust tests, and E2E Scenario E in `multi-entry.spec.ts` (type → toggle Timeline → toggle back, ×3, real TipTap).** **Completed (2026-07-28): E2E Scenario E exposed two further root causes in the same failure chain, both now fixed and verified against the release binary. (2) *Title focus steal* — `TitleEditor`'s auto-focus was a `createEffect` reading `props.readOnly` (= `currentLocked()`, derived from `dayEntries`/`currentIndex`), so it re-focused the title input on every entry-list change, including the `setDayEntries` inside `startEntryCreation` that fires mid-typing: the caret left the body and the rest of the sentence was typed into the title. Fixed by switching to `onMount` (1 unit test, verified failing against the old code). Verification: `multi-entry` spec 4/4 green and full E2E suite 5/5 green twice; the pre-fix binary failed Scenario E 3/3.**

- [ ] **TODO-0088: Fix `website:build-static` on Windows checkouts — CRLF hash rotation and flaky writes** — two independent defects in `scripts/fingerprint-website-assets.mjs`, both hit while regenerating docs for TODO-0072 (2026-07-27). Neither is caused by content changes, and both make the script actively unsafe to run from a Windows checkout without manual cleanup.
  - [ ] **CRLF-derived asset hashes rotate every generated HTML file** — `shortHash()` hashes the raw working-tree bytes of `website/css/style.css` and `website/js/main.js`. Those two files are stored LF in the index but checked out CRLF on Windows (`git ls-files --eol` → `i/lf w/crlf`; no `.gitattributes` rule covers them), so the script computes different hashes than CI does and rewrites the `<link>`/`<script>` refs in **~45 files** — every blog post, every docs page, `privacy/`, `compare/`, `donate/`, `newsletter/`, `encrypted-journal/` — plus deletes and re-creates the hashed asset copies. Committing that flips the hashes back and forth on every platform switch and buries real content diffs. **Interim workaround used:** normalize both files to LF before running (`[IO.File]::WriteAllText($f, ($t -replace "\`r\`n", "\`n"))`), which reproduces the committed `style.82ae551a.css` / `main.1ba3bbe1.js` hashes exactly. **Fix:** add `website/css/*.css text eol=lf` + `website/js/*.js text eol=lf` to `.gitattributes` (matching the existing `docs/diagrams/*.svg` rule, which exists for this identical "regenerated output must match committed bytes on all platforms" reason), or normalize line endings inside `shortHash()` before hashing. Prefer `.gitattributes` — it fixes the bytes at their source rather than papering over them at hash time.
  - [ ] **Intermittent `UNKNOWN: open` failures mid-run leave the tree half-rewritten** — the `writeFileSync` at `scripts/fingerprint-website-assets.mjs:112` fails with `errno: -4094` / `code: 'UNKNOWN'` on freshly written HTML (likely AV real-time scanning holding a handle). It failed on a different file each run and needed **5 attempts** to complete. Because the script writes in a bare loop with no retry and no atomicity, a mid-run failure leaves some HTML rewritten and some not, with a non-zero exit and no rollback. **Fix:** wrap the write in a small retry-with-backoff helper (a few attempts is enough — every failure here cleared on retry), and consider write-to-temp + rename for atomicity. Note the same class of Windows flakiness is already documented for this command in root `CLAUDE.md` (it is listed under "Commands with side effects" and must be run via the PowerShell tool).
