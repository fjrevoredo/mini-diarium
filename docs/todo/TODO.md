- [x] **TODO-0068: Auto-lock on window minimize, close, or lose-focus (#194)** — added an optional `autoLockOnFocusLoss` toggle (off by default, "Lock when the window loses focus" in Preferences → Security), independent of the idle-timer lock, that locks the journal on any OS-level focus loss: minimize, Alt+Tab/Cmd+Tab away, clicking another app's window, or (on macOS) Cmd+H "Hide". Went through three design iterations: (1) the originally planned frontend-only `visibilitychange`/`blur` approach was disproven by manual testing (WebView2 does not reliably fire `visibilitychange` on minimize, confirmed with the CDP debugger fully detached to rule out a tooling confound) and replaced with a Rust-side `Window::is_minimized()` poll; (2) that minimize-only design was itself replaced after live testing showed alt-tab/click-away didn't trigger the lock — user feedback confirmed the intent was "any focus loss," matching the original issue title, and replaced with `WindowEvent::Focused(false)`; (3) the immediate-lock version from (2) was reported as too aggressive — a misclick outside the window locked the journal instantly — so a debounce was added. Final design: `src-tauri/src/window_focus.rs` emits `"window-unfocused"`/`"window-focused"` from `on_window_event` on `WindowEvent::Focused` (push-based, verified via tao source to be reliably forwarded on Windows/macOS/Linux — unlike minimize/iconify, which Linux's GTK backend only tracks internally); `src/lib/focus-lock.ts` debounces the lock by `FOCUS_LOSS_DEBOUNCE_MS` (3s default, parametrized via an options field for easy retuning) — `window-unfocused` starts the timer, `window-focused` cancels it, so a quick misclick doesn't lock. Native dialogs (export/import/key-file save, etc.) also resign the main window's focus, so `src/lib/dialog.ts` (a wrapper around `@tauri-apps/plugin-dialog`'s `open`/`save`/`confirm`, now used by all 11 call sites) tracks an open-dialog count that `focus-lock.ts` re-checks via `isDialogOpen()` when the debounce fires. Known gap: this only covers the app's own dialogs, not the native menu bar or other external focus-stealers — closing that fully would need a "does the focused window belong to our process" check, unreliable on Linux/Wayland, so it was deliberately not attempted. Verified end-to-end on Windows (event fires on minimize, journal actually locks, survives restore) with the CDP debugger detached each time; alt-tab/cross-app focus-loss specifically could not be safely simulated from the automation harness (it runs on the real interactive desktop, and focus-stealing attempts risk disrupting concurrent user work) — rests on the tao source-level guarantee plus a manual pass being recommended before full trust; macOS/Linux rest on source inspection only, not live-tested; debounce value (3s) may need retuning based on further user feedback
