- [x] **TODO-0088: Fix `website:build-static` on Windows checkouts — CRLF hash rotation and flaky writes** — two independent defects in `scripts/fingerprint-website-assets.mjs`, both hit while regenerating docs for TODO-0072 (2026-07-27). Neither is caused by content changes, and both make the script actively unsafe to run from a Windows checkout without manual cleanup. **Done 2026-07-29:** both layers applied — `.gitattributes` pins `website/` css/js/html/xml/txt to `eol=lf` (25 working-tree files renormalized) and `shortHash()` normalizes `\r\n` before hashing, writing those same normalized bytes as the hashed copy. The script is now idempotent (compares before writing; `0 updated / 38 unchanged` on a no-op run), hoists the per-asset hash out of the HTML loop, and retries writes with backoff. New `scripts/fingerprint-website-assets.test.mjs` covers the pure helpers. Verified on Windows: committed `style.82ae551a.css` / `main.1ba3bbe1.js` reproduce exactly, a deliberately CRLF-ified `style.css` still yields `82ae551a` and zero writes, and a real CSS change still propagates to all 38 HTML files. CI wiring for the orphaned `scripts/*.test.*` files is tracked as TODO-0093.
  - [x] **CRLF-derived asset hashes rotate every generated HTML file** — `shortHash()` hashes the raw working-tree bytes of `website/css/style.css` and `website/js/main.js`. Those two files are stored LF in the index but checked out CRLF on Windows (`git ls-files --eol` → `i/lf w/crlf`; no `.gitattributes` rule covers them), so the script computes different hashes than CI does and rewrites the `<link>`/`<script>` refs in **~45 files** — every blog post, every docs page, `privacy/`, `compare/`, `donate/`, `newsletter/`, `encrypted-journal/` — plus deletes and re-creates the hashed asset copies. Committing that flips the hashes back and forth on every platform switch and buries real content diffs. **Interim workaround used:** normalize both files to LF before running (`[IO.File]::WriteAllText($f, ($t -replace "\`r\`n", "\`n"))`), which reproduces the committed `style.82ae551a.css` / `main.1ba3bbe1.js` hashes exactly. **Fix:** add `website/css/*.css text eol=lf` + `website/js/*.js text eol=lf` to `.gitattributes` (matching the existing `docs/diagrams/*.svg` rule, which exists for this identical "regenerated output must match committed bytes on all platforms" reason), or normalize line endings inside `shortHash()` before hashing. Prefer `.gitattributes` — it fixes the bytes at their source rather than papering over them at hash time.
  - [x] **Intermittent `UNKNOWN: open` failures mid-run leave the tree half-rewritten** — the `writeFileSync` at `scripts/fingerprint-website-assets.mjs:112` fails with `errno: -4094` / `code: 'UNKNOWN'` on freshly written HTML (likely AV real-time scanning holding a handle). It failed on a different file each run and needed **5 attempts** to complete. Because the script writes in a bare loop with no retry and no atomicity, a mid-run failure leaves some HTML rewritten and some not, with a non-zero exit and no rollback. **Fix:** wrap the write in a small retry-with-backoff helper (a few attempts is enough — every failure here cleared on retry), and consider write-to-temp + rename for atomicity. Note the same class of Windows flakiness is already documented for this command in root `CLAUDE.md` (it is listed under "Commands with side effects" and must be run via the PowerShell tool).
